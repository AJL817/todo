# 백로그 (P1, 이번 범위 밖)

`docs/PRD.md` §4 P1 목록에서 이월(A11)만 P0 로 승격해 구현했고, 나머지는 여기에 남긴다.
승격 근거는 `docs/PLAN.md` §0.3 — 이월이 없으면 지난 주 진행률이 영영 100% 에 닿지 못하고,
사용자가 이를 우회하려고 할일을 지우는 순간 지난 주가 100% 로 잘못 올라간다. 즉 편의 기능이
아니라 진행률 산식의 정합성 문제였다.

## 우선순위 재조정 규칙

순서는 취향이 아니라 `docs/PLAN.md` §1.5 지표가 정한다. `npm run metrics` 결과를 보고 고른다.

| 조건 | 먼저 넣을 것 | 이유 |
|---|---|---|
| **M1 < 70%** (주간 계획 연결률) | 할일 생성 시 주간 계획 기본값 자동 제안 | 미분류가 쌓이면 "할일과 목표를 잇는다" 는 제품 목적 자체가 작동하지 않는다. 태그나 우선순위보다 급하다 |
| **M3 > 15%** (이월 적체율) | 3회 이상 이월된 항목 경고 | 이월이 "다음 주로 미루기" 습관으로 굳는 신호다 |
| 셋 다 목표 달성 | 아래 목록 순서대로 | — |

## 목록

### 1. 반복 할일 (일간 / 주간 주기)
생성 시 주기를 지정하면 자동으로 다음 인스턴스를 만든다.

주의할 점: 반복 항목이 진행률 분모에 어떻게 들어갈지 먼저 정해야 한다. 매일 생성되는
항목이 주간 분모를 지배하면 나머지 할일의 기여도가 묻힌다. `docs/PLAN.md` §0.2 에서
가중 평균을 버린 것과 같은 종류의 문제다.

### 2. 주간 회고 메모 필드
`WeeklyPlan` 에 자유 서술 필드를 추가한다. 스키마 변경만 놓고 보면 가장 작지만,
주간 뷰 화면에 자리를 만들어야 한다.

### 3. 1년 목표 하위 주간 진행률 추이 그래프
경과 주별 진행률을 시계열로 보여 준다. 데이터는 이미 있다 —
`goalRepo.getGoalWithProgress` 가 주별 진행률을 배열로 돌려주므로 화면만 붙이면 된다.

`counted` 플래그를 그래프에서도 구분해야 한다. 미도래 주를 0% 로 그리면
A5 로 막아 둔 왜곡이 그래프에서 되살아난다.

### 4. 할일 태그 / 우선순위 필드 및 필터
`Todo` 에 `tags: string[]`, `priority` 를 추가하고 보드에 필터를 단다.
`strict: 'throw'` 스키마이므로 모델과 Zod 스키마를 함께 고쳐야 한다.

### 5. 키보드 단축키 기반 상태 변경
`@dnd-kit` 의 `KeyboardSensor` 는 이미 `components/KanbanBoard.tsx` 에 붙어 있어
드래그의 키보드 대체는 일부 확보돼 있다. 남은 것은 단축키 정의와 안내다.

카드마다 있는 ← / → 버튼(`move-left` / `move-right`)이 이미 드래그 없는 상태 변경
경로를 제공하므로, 접근성 최저선은 지금도 충족된다.

### 6. 소프트 삭제 항목 복구 뷰
`deletedAt !== null` 인 항목을 보여 주고 되살린다. 보관 기한 30일 안에서만 의미가 있다
(`lib/retention.ts`).

복구 시 주의: `weeklyPlanId` 가 가리키던 주간 계획이 그 사이 하드 삭제됐을 수 있다.
되살린 항목이 미분류로 떨어지는 것이 맞는지 정해야 한다.

## 로그인 이후 남은 것

`docs/LOGIN.md` 의 완료 조건은 모두 구현했다. 아래는 그 위에 얹을 수 있는 것들이며
요구사항에 없어 넣지 않았다.

- **세션 목록과 개별 로그아웃** — `destroyAllSessionsOfUser` 는 이미 있다. 화면만 붙이면 된다
- **계정 삭제** — 사용자와 그 데이터를 함께 지우는 경로. 소프트 삭제 정책과의 관계를 먼저 정해야 한다
- **여러 계정을 한 브라우저에서** — 현재는 로그아웃 후 다시 로그인해야 한다
- **GitHub 외 제공자** — `lib/auth/github.ts` 를 제공자별로 나누면 되지만, 1인용 앱에 필요한지 먼저 판단할 것
